# Flux 1.3 — 2026-05-21

One headline feature and two bug fixes. Flux now sends push notifications when the battery crosses a threshold inside a time window you define — opt-in, per device, up to ten rules each. Overnight, the dashboard no longer locks to "0% / 0 W everywhere" when AlphaESS goes quiet; a new backfill CLI repairs past dates affected by the same outage.

## What's New

### SoC Alerts (T-1288)

A new **Settings → Alerts** screen on iOS and macOS lets you create push-notification rules tied to the battery's state of charge. Each device manages up to **10 rules**:

- **Threshold** (1–99 %) — fires on a downward crossing only (going below, not coming back up through).
- **Window** — `HH:MM` start and end in your device's local time zone. Cross-midnight windows are supported (e.g. `22:00 → 06:00`).
- **Enabled** toggle.
- Optional 40-character **label** ("Morning floor", "Evening reserve", "Backup buffer").

Rules fire **at most once per window per day**, so a noisy battery dropping repeatedly across the threshold won't spam your lock screen.

The screen mirrors the rest of the app's Liquid Glass styling, surfaces inline banners for the two failure modes (notification permission denied, backend unreachable), and uses the same idempotent device-registration flow the widgets use: a POST only goes out when the APNs token or the time zone has actually changed, and a foreground hook replays any registrations that were pending while the app was backgrounded.

**Per-device APNs environment**. The backend honours each device's APNs environment (`development` for Xcode debug builds, `production` for TestFlight and App Store builds) so two devices on different build types can coexist on the same backend without one of them silently 400-ing every push. The Swift app reads its own `aps-environment` entitlement at runtime and includes it in the registration payload; the Go poller routes each push to the matching APNs host (sandbox vs production) using the environment carried on the device row.

**Backend mechanics**. The Go poller evaluates every enabled rule each 10 s cycle and dispatches APNs pushes via `sideshow/apns2` through a bounded 4-worker queue (capacity 64) so a slow APNs RTT can't stall the poll cadence. The same `(deviceId, ruleId, windowStartDate)` triple becomes the APNs `collapse-id` (`base64url(sha256(...))[:22]`), so on the rare occasion two pushes do escape, the device collapses them into one. Fire-state rows are written conditionally **before** the push enqueue, so a poller crash leaves at most a silent miss rather than a duplicate alert.

**Three new DynamoDB tables** back the feature:

- `flux-devices` — registered devices (PITR).
- `flux-soc-rules` — alert rules (PITR).
- `flux-soc-fire-state` — fire history (TTL 7 d, no PITR).

Lambda gains four new endpoints behind the existing bearer-token middleware: `POST /devices`, `GET /devices/{id}/rules`, `POST /devices/{id}/rules`, `PUT /devices/{id}/rules/{ruleId}`, `DELETE /devices/{id}/rules/{ruleId}`. Rule mutations cascade-clean the affected fire-state rows so the next poll cycle re-arms under the new configuration. A daily orphan GC step inside the midnight finalizer drops devices that haven't registered for 30 days (with a 24-hour in-flight fire-state guard and a conditional delete on `lastRegisteredAt` to survive the re-registration race).

### `cmd/backfill-readings` CLI (T-1274)

Companion to the overnight zeros fix below. For a date range, this one-off tool:

1. Scans `flux-readings` for all-zero rows produced during the AlphaESS overnight outage.
2. Removes them.
3. Replaces them with synthetic 5-minute readings derived from the daily-power snapshot (`getOneDayPowerBySn`), using the same field mapping the Day Detail past-date fallback already uses (`cbat → soc`, `gridCharge − feedIn → pgrid`, `load − ppv − pgrid → pbat`).

Supports `--dry-run` to preview the planned writes/deletes before committing. Defaults to the trailing 3 days; pass `--from` and `--to` for a specific range. Patched rows still respect the existing 30-day `flux-readings` TTL.

## Fixes

- **Dashboard no longer shows "0% / 0 W everywhere" overnight** (T-1274). When AlphaESS goes quiet at night, `getLastPowerData` returns `code:200` with `data: null` or an all-zero object. The poller previously unmarshalled the missing payload into a zero-valued `PowerData` and wrote a fresh `ReadingItem` with every field zero — and `/status` surfaced those zeros as the live readout, so the dashboard claimed SoC was 0 % and nothing was running until backfill caught up. Three reinforcing fixes ship together:
  - `GetLastPowerData` now treats null/empty `data` as an error, so the poller logs and skips it instead of writing a zero row.
  - The poller's `fetchAndStoreLiveData` refuses to persist every-field-zero readings and logs the raw values at warn level, so the overnight AlphaESS behaviour is visible in CloudWatch.
  - `/status` drops `live` (and the cutoff times derived from it on `battery` and `rolling15min`) when the most recent stored reading is older than 90 s, so the dashboard's existing "Awaiting live data" state surfaces instead of holding aged numbers.

  The user-visible effect: between roughly midnight and first light, the dashboard shows the awaiting-data state rather than a wall of zeros. Existing zero rows in `flux-readings` can be repaired with the new `cmd/backfill-readings` CLI.

## Upgrade Notes

### Backend

- **Push the new poller image and redeploy the Lambda** in the usual order. The new endpoints and the SoC-alerts evaluation loop ship with these binaries. Force a poller redeploy with:
  ```bash
  aws ecs update-service --cluster flux --service flux-poller --force-new-deployment
  ```
- **New infrastructure** (managed by `infrastructure/template.yaml`): three DynamoDB tables (`flux-devices`, `flux-soc-rules`, `flux-soc-fire-state`) and new IAM permissions for the poller and Lambda. Deploy the updated stack the usual way (`aws cloudformation package` → `aws cloudformation deploy`).
- **APNs credentials** (one-time, before SoC alerts can fire). Add the following SSM parameters — the per-device-environment work means there is no longer a sixth `/flux/apns/env` parameter:
  - `/flux/apns/team-id`
  - `/flux/apns/key-id`
  - `/flux/apns/bundle-id` (use the exact bundle ID, casing matters — see T-1309)
  - `/flux/apns/key-p8` (SecureString — the contents of the `.p8` from Apple Developer)
- **No-op for existing data**. The new tables start empty; existing `/status`, `/history`, and `/day` paths are unchanged.

### Backfill past gaps (optional)

If your `flux-readings` table still has all-zero rows from before this release deployed, patch them with the new CLI (within the 30-day TTL window):

```bash
go run ./cmd/backfill-readings --from 2026-04-21 --to 2026-05-21
# add --dry-run first to see what it would write
```

### iOS / macOS

- Standard App Store / TestFlight update.
- After updating, open **Settings → Alerts** to register your device and create rules. The first time you tap **Add rule**, you'll be prompted for notification permission. If you deny, the screen surfaces a banner with the path back into iOS / macOS Settings to re-enable.

### Breaking changes

None for end users. Backend operators should note the new required SSM parameters above (alerts will simply not fire if they are missing — the existing `/status`, `/history`, `/day` paths are unaffected).
