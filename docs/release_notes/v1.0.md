# Flux 1.0 — 2026-05-07

First public release of Flux: a personal AlphaESS battery monitoring system spanning an AWS backend, a SwiftUI iOS app, and a native macOS app, with home-screen and lock-screen widgets shared across iOS and macOS.

## Breaking Changes

- **CloudFormation off-peak parameters now mandatory.** `OffPeakWindowStart` and `OffPeakWindowEnd` no longer have default values. Supply both on every deploy via `--parameter-overrides` or a parameters file. Values are validated against `AllowedPattern` at deploy time so YAML 1.1 sexagesimal parsing cannot silently turn `11:00` into the integer `660` again.

  Migration: add the two parameters to your existing deploy invocation. No changes to running infrastructure.

## What's New

### Backend (AWS)

A single CloudFormation stack provisions everything: a VPC with public subnets, an ECS Fargate cluster running an ARM64 poller container, a Lambda Function URL serving the API (ARM64, `provided.al2023`), six DynamoDB tables on PAY_PER_REQUEST, SSM Parameter Store for credentials, and CloudWatch Logs with 14-day retention. All IAM is least-privilege and ARN-scoped.

The **AlphaESS poller** polls on four schedules: 10 s for live battery data, 1 h for daily power, 6 h for daily energy, 24 h for system info. It snapshots off-peak energy at window boundaries with retry plus crash recovery, and runs an hourly summarisation pass that pre-computes per-day derived stats (`dailyUsage`, `socLow`, `peakPeriods`) for yesterday into `flux-daily-energy`. A `SummarisationPassResult` CloudWatch metric with six result dimensions (`success`, `error`, `skipped-no-readings`, `skipped-no-row`, `skipped-ssm-unresolved`, `skipped-already-populated`) gives operational visibility. The `/poller healthcheck` subcommand backs the ECS health probe.

The **Lambda API** exposes three GET endpoints — `/status`, `/history?days=N`, `/day?date=YYYY-MM-DD` — plus a `PUT /note` write endpoint. Bearer-token auth via constant-time comparison; SSM-backed credentials. The response shape includes battery info with cutoff prediction, rolling 15-minute averages, sustained grid detection, off-peak deltas, today's energy via trapezoidal integration of readings reconciled against stored daily totals, peak-period clusters, the five-block daily-usage breakdown, and an off-peak grid import/export split on `/day`. `/history` now serves pre-computed daily stats from storage instead of recomputing them from ~258k readings on every 30-day call.

**Day Notes** add a per-date free-text note (200 grapheme clusters, NFC-normalised). Empty text deletes idempotently. Notes bundle into the read responses via a soft-fail goroutine outside the main errgroup so a notes-table failure logs and leaves the field `nil` without cancelling siblings. Identical grapheme rules on Swift and Go are pinned by the shared `internal/api/testdata/note_lengths.json` fixture, exercised on both sides.

### iOS app

iOS 26+ SwiftUI app with **Dashboard**, **History**, **Day Detail**, and **Settings** screens, built around `@Observable` view models on the main actor. Auto-refresh every 10 s on Dashboard with `scenePhase` pausing, pull-to-refresh, SwiftData caching of historical days, App-Group Keychain for the API token.

The **V5 redesign** ships a custom three-segment tab bar above each screen (replacing `NavigationSplitView` on iOS), Liquid Glass panels, a Dashboard hero with selectable font and "discharging · X · empty by HH:MM" subline, a live solar/house/grid trio panel, and a "Day in five blocks" stacked-bar panel pinned to the top of Day Detail.

New panels and cards:

- **Peak Usage card** — top three high-load periods of the day with time range, average load, and energy.
- **Daily Usage card** — up to five chronological no-overlap blocks (Night / Morning Peak / Off-Peak / Afternoon Peak / Evening) with kWh, average kWh/h, percent of day, status, and an `≈ sunrise` / `≈ sunset` caption when boundaries are estimated rather than read from a real sun-up reading.
- **History Daily Usage card** — multi-day stacked-bar variant of the same five-block breakdown across the active 7/14/30-day range.
- **History Usage Stats overview card** — eight tiles: Total usage, Total solar, Exported, Peak imports, Avg night, Most usage, Most solar, Lowest SoC. Day-record tiles tap through to Day Detail.
- **BatteryBlock panel** — battery cycle, lowest SOC with timestamp, and an optional "Charged during off-peak" delta. Used on Dashboard and Day Detail.
- **Day Notes UI** — a read-only `NoteRowView` on Dashboard, History, and Day Detail; tap on Day Detail to edit via `NoteEditorSheet` with NFC normalisation, 200-grapheme cap, and a remaining-characters counter.
- **Household load row** — total usage on the Dashboard, History day-summary, and Day Detail summary cards. Derived from the energy balance (`solar + grid_import + battery_discharge − grid_export − battery_charge`) with em-dash fallback when any input is missing.

Settings gains:

- **Light / Dark / Follow System** theme picker, applied at the app root and persisted to the App Group.
- **App-wide font picker** listing every font family installed on the device. Applies to every text element while preserving Dynamic Type. Tabular tokens (digits, time ranges) deliberately stay on the system monospaced font so columns stay aligned.

### macOS app

Native macOS 26+ build (T-1081). **Not** Mac Catalyst; **not** Designed-for-iPad. Shares `FluxCore`, views, and the widget extension with iOS. Highlights:

- Dedicated `Settings { ... }` scene opened via ⌘,, single main window that quits on close, ⌘R refresh dispatched through a `FluxRefreshCoordinator`, ←/→ Day Detail navigation, `@SceneStorage`-persisted sidebar selection.
- Liquid Glass styling via `.scrollContentBackground(.hidden)` and `.backgroundExtensionEffect()`.
- Activity tier bound to `@Environment(\.appearsActive)`: 10 s refresh when the main window is key, 60 s when not.
- Credential sync: API token via iCloud Keychain (`kSecAttrSynchronizable = true`, `kSecAttrAccessibleAfterFirstUnlock`), URL via `NSUbiquitousKeyValueStore` mirrored into the App Group `UserDefaults`.
- **Control Center widget** using Apple's `ControlWidget` protocol with an `OpenURLIntent("flux://dashboard")` tap target.
- `make macos-build`, `make macos-test`, `make macos-lint` Makefile targets.

### Widgets

Home-screen widgets (`systemSmall`, `systemMedium`, `systemLarge`) and lock-screen accessories (`accessoryCircular`, `accessoryRectangular`, `accessoryInline`) showing battery state of charge, plus the solar / house / grid power trio where the family size allows. Widgets refresh independently from the host via the shared App Group cache (`group.me.nore.ig.flux`) plus a direct Lambda fetch with the shared Keychain bearer token. `flux://dashboard` deep link opens the app at the Dashboard.

The **medium widget redesign** sits the SOC reading inside a circular progress ring; the right column renders four matched pill rows (Solar / Load / Grid / battery state + rate). Cutoff-risk colouring tints the ring and battery row together — red within 2 h, orange before off-peak — with `BatteryColor.forSOC` as fallback. A Settings toggle **"Widget icons instead of labels"** switches medium-widget row labels between text and SF Symbols, with symbols inheriting each row's semantic colour. An "Empty" row shows the 15-minute rolling-average cutoff time when discharging.

## Notable Behaviour Changes

- **`battery.low24h`** now means "lowest SOC since Sydney-local 00:00 on `now`'s date" — i.e. lowest today. Nil only briefly each day after midnight before the first reading lands. UI labels are now "Lowest" everywhere.
- The **30-day TTL on `flux-daily-power`** has been removed. Day Detail's past-date fallback works indefinitely instead of stopping at 30 days. Replaces an abandoned S3-archive plan; at ~21 MB/year per system the rows stay in DynamoDB cheaply.
- **`/status` cutoff suppression**: `estimatedCutoffTime` is omitted when the extrapolated cutoff falls at or after the next off-peak window — the battery will be charged during that window so the prediction would be misleading.

## Notable Fixes

- **Evening/Night stray-blip filter**: a sensor `Ppv > 0` blip at e.g. 01:30 no longer ends the Night block at 01:30 or starts a 22-hour "evening". The scan ignores any reading whose timestamp is before `sunrise − 30 min`.
- **Dashboard "Charged during off-peak" row** is reserved with an em-dash even when the delta is nil (e.g. before today's window has produced data) instead of vanishing.
- **`computeCutoffTime`** guards against NaN/Inf from very small `pbat` values and rejects `capacityKwh <= 0`.
- **Unused CloudKit/iCloud entitlements** removed from the iOS app, fixing App Store Connect upload error 90046.

## Upgrade Notes

- This is the initial release; no upgrade path required.
- Provision SecureString SSM parameters before first deploy:
  ```bash
  aws ssm put-parameter --name "/flux/app-secret" --type SecureString --value "SECRET"
  aws ssm put-parameter --name "/flux/api-token"  --type SecureString --value "TOKEN"
  ```
- Build and deploy:
  ```bash
  GOOS=linux GOARCH=arm64 go build -o lambda/bootstrap ./cmd/api
  aws cloudformation package \
    --template-file infrastructure/template.yaml \
    --s3-bucket BUCKET \
    --output-template-file infrastructure/packaged.yaml
  aws cloudformation deploy \
    --template-file infrastructure/packaged.yaml \
    --stack-name flux \
    --capabilities CAPABILITY_IAM \
    --parameter-overrides ContainerImageUri=ghcr.io/OWNER/flux-poller:latest \
      AlphaESSAppId=APP_ID SystemSerialNumber=SERIAL \
      OffPeakWindowStart=11:00 OffPeakWindowEnd=14:00
  ```
