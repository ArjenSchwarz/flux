# Flux 1.6 — 2026-06-10

Two additions and a consistency change. History gains week-to-date and month-to-date ranges alongside the fixed windows, and the Dashboard can now run a what-if — "what happens to my battery if I charge the car right now?" — without touching any device. History's overview totals also start counting today, so a freshly-started week or month shows real numbers instead of em-dashes.

## What's New

### Week-to-date and month-to-date History ranges (T-1361)

The History range control gains two calendar-anchored options — **Wk** (this week so far) and **Mo** (this month so far) — alongside the fixed 7/14/30-day ranges, for a five-segment control in the order 7d / 14d / 30d / Wk / Mo, with 7d still the default. Period boundaries are computed against the same Sydney calendar that keys the stored data, with the week's first day taken from your device locale, and they recompute on every load — range switch, pull-to-refresh, and screen appearance — so the window is always current.

A partly-elapsed week or month draws its bars left-aligned with empty space held for the days not yet elapsed: Wk reserves the full seven-day week, Mo the full calendar month. The layout therefore stays stable from the first day of the period instead of a lone bar stretching across the width. The fixed 7/14/30-day ranges are unchanged.

Two supporting changes keep the new ranges accurate. The `/history` endpoint now accepts any range from 1 to 31 days, so a full month-to-date on the 31st of a 31-day month is no longer clipped to 30. And the offline cache fallback is bounded by the computed week/month start and auto-selects the newest cached day — matching the online behaviour — so a gappy cache never surfaces a day before the period start.

### Dashboard Simulation (T-1495)

A new **Simulate** pill sits in the Dashboard hero, beside the battery percentage on iPhone, iPad, and macOS. Tapping it applies a saved load preset — for example "Charge car" at 1.7 kW — as a clearly-labelled what-if: the Dashboard shows how house load, battery flow, and the "empty by" estimate would change if that load were running right now, without sending anything to your battery or inverter.

The figures are computed on the backend, using the same logic as the real Dashboard, so a simulation never disagrees with the live numbers. The battery is shown discharging up to its limit with any excess drawn from the grid; on a sunny day, the added load is taken from your solar export first. The picture is therefore accurate whether you're on grid power in the evening or soaking up solar at midday.

While a what-if is active, the pill takes the simulation accent with a dot, and a distinct banner plus tinted values make it obvious the numbers are simulated. The simulation clears when you turn it off or relaunch the app. Manage presets (label + watts) in **Settings → Simulation**. iOS and macOS.

## Changes

### History overview totals now include today

Total solar, Total usage, Most usage, and Most solar — and the Battery card's discharged/charged totals — now count today's value, matching Peak imports, Exported, and Lowest SoC, which already did. A range whose only data is today (for example Week-to-date on the week's first day) now shows real numbers and the daily-usage bar instead of em-dashes. Per-day averages (Solar/day, Battery/day, Daily-usage/day, Avg night) still exclude today's partial day so they aren't skewed by a half-finished day.

## Upgrade Notes

No breaking changes. This release pairs the iOS/macOS app with a backend update for the simulation figures and the widened history range. The `/history` change (1–31 days) is backward compatible — existing requests for 7, 14, or 30 days behave exactly as before. Dashboard Simulation is additive and entirely user-initiated; presets are stored on-device, and a simulation only ever computes a hypothetical view — it never writes to your battery, inverter, or the backend's stored data.
