# Flux 1.2 — 2026-05-13

Two user-facing additions and two bug fixes. Every chart card across History and Day Detail now has a tap-to-enlarge button. Day Detail gains an opt-in Compare toggle that shows per-row deltas against Yesterday or 7 days ago. The combined battery chart's SOC fill is recoloured so it no longer blends into the off-peak band, and the post-midnight gap on past-date Day Detail charts is closed.

## What's New

### Zoom in on Graphs (T-1215)

Every chart card on History (Solar, Grid Usage, Daily Usage) and Day Detail (Power, Combined battery) now carries an `arrow.up.left.and.arrow.down.right` expand button in its top-trailing corner. Tapping it opens the chart enlarged. The enlarged view reuses the inline card body byte-for-byte, so the styling, selection overlay, and accessibility behaviour are identical to what the user already knows from the embedded card.

**iOS** presents the enlarged chart as a landscape `fullScreenCover`. A 32 pt drag-handle pill sits above the title; dragging it down past 60 pt dismisses the cover. Upward and mostly-horizontal drags are inert so a chart-area swipe doesn't accidentally close the view. A Close button (xmark) in the top bar handles VoiceOver and the Reduce-Motion case. The cover survives backgrounding via `@SceneStorage("expandedChart")` (chart kind only — the data scope falls back to the History 7-day default if the user backgrounded with a 14- or 30-day range).

**macOS** opens the enlarged chart as a separate window: `WindowGroup(for: ChartKind.self)` with a 900×600 default size and 720×480 minimum, suppressed launch-restore, and `.windowManagerRole(.associated)` so the window appears in the Window menu without claiming main role. Window identity is keyed on `ChartKind` only, so re-expanding the same chart from a different context brings the existing window forward; different chart kinds open additional windows. Each window owns its own `ChartSceneObserver` polling at 60 s, scoped to the window's `appearsActive` state — inactive windows pause, and reactivating triggers an immediate refetch on the next tick. A failed refetch leaves the previously displayed snapshot intact.

The two Day Detail charts share their `selectedDate` between the inline card and the enlarged view, so opening the enlarged chart while a reading is selected preserves the selection. Mid-interaction data refreshes are deferred so the chart can't shift under the user's finger: History uses a `DragGesture`-driven `HistoryDragGate` (refresh held in `pending`, flushed once on drag end), and Day Detail uses an `XSelectionQuiescenceGate` with a 400 ms quiet window after the last `chartXSelection` change (cleared selection flushes immediately).

VoiceOver / keyboard focus returns to the originating expand button on dismissal — coordinated via a small `ChartExpansionFocusCoordinator` shared between the iOS root view and the macOS chart scene. Reduce Motion replaces the system presentation transition with a 200 ms `easeInOut` opacity cross-fade. Dynamic Type carries through unchanged because the enlarged hosts reuse the same `appFont(.textStyle:)` callsites as the inline cards. WCAG-AA contrast for the expand-button glyph (`FluxTheme.Palette.secondaryText`) was verified against the lightest in-scope chart fills in light mode (5.25 : 1, 4.31 : 1, 4.71 : 1 — all above the 3 : 1 graphical-object floor).

### Stat Comparisons on Day Detail (T-1161)

Day Detail gains an opt-in Compare toggle above the "Day in five blocks" panel. When on, every summary value and every five-block value column gets a sub-line showing the absolute-kWh delta against the comparison day, with an ▲ / ▼ / — arrow:

- **Summary block**: Solar produced, House used, Grid in (peak), Grid in (off-peak), Grid out.
- **Day in five blocks**: per-block solar and total on the morning peak, off-peak, and afternoon peak rows. Night and evening rows show only the total delta.

A period chip on the toggle row switches the comparison between **Yesterday** and **7 days ago**. Both the toggle state and the period are remembered per-device via `@AppStorage` and reapply automatically when you reopen Day Detail or move to a different day.

VoiceOver reads the comparison label inline with each value (e.g. "Solar produced 18.4 kilowatt-hours, 2.1 kilowatt-hours more than yesterday"). When the comparison day's data is unavailable (e.g. the date predates your data, or a network failure), the row reserves space with an em-dash rather than collapsing the layout.

The comparison fetches the comparison day from the existing `/day` endpoint — no backend changes required, and only one extra request per period change. In-flight comparison fetches are cancelled when you change the toggle, the period, or the selected day.

## Notable Behaviour Changes

- **Day Detail combined battery chart — SOC colour**. `Palette.soc` shifts from cream (`#FFD089`) to coral (`#FFA866`). The previous cream blended into the yellow off-peak window rectangle where the two overlapped (typically 11:00–14:00 Sydney), making the SOC area hard to read inside the off-peak band. The coral provides clear separation while still sitting comfortably alongside the existing battery palette.
- **Daily-power retention through midnight**. Day Detail charts for past dates no longer have a 5–10 minute gap at the end (~23:05–23:10). See *Fixes* below for the full description; the user-visible effect is that yesterday's Power and Combined-battery charts now run cleanly to 23:55.

## Fixes

- **Post-midnight daily-power gap** (T-1206 / #45). `pollDailyPower` only ever asked AlphaESS for today's snapshots, so after Sydney midnight the readings between the last pre-midnight hourly tick and 23:55 were permanently absent from `flux-daily-power`. Two layered fixes:
  - The hourly poll now requests today AND yesterday (mirroring the existing T-841 fix on `pollDailyEnergy`).
  - A dedicated midnight-finalizer goroutine re-fetches yesterday's daily power and energy and re-runs the derived-stats summarisation 15 min after each Sydney midnight.
  The deepest possible gap shrinks from "permanently missing" to "at most 15 min after midnight." Existing past dates can be patched with the new `cmd/backfill-daily-power` CLI.
- **SOC area / off-peak band visual distinction** (#46). `Palette.soc` recoloured (see above) so the SOC fill no longer disappears inside the yellow off-peak window rectangle on the Day Detail combined battery chart.

## Upgrade Notes

- **Backend**: the `pollDailyPower` change ships with the next poller container deploy. The midnight-finalizer goroutine starts on the next ECS task launch — no configuration required. Force a redeploy with:
  ```bash
  aws ecs update-service --cluster flux --service flux-poller --force-new-deployment
  ```
- **Backfill past gaps** (optional): rows already in `flux-daily-power` are not retroactively repaired by the running fix — they were written with gaps. Run the new CLI to patch them within the 30-day TTL window:
  ```bash
  go run ./cmd/backfill-daily-power --from 2026-04-13 --to 2026-05-13
  # add --dry-run first to see what it would write
  ```
- **iOS / macOS**: standard App Store / TestFlight update. The Compare toggle defaults to off; the expand affordance is always present on the five active chart cards.
- **No infrastructure changes required**.
