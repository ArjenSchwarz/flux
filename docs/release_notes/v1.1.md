# Flux 1.1 — 2026-05-09

First post-1.0 update. Adds per-block solar to Day Detail, a usable-energy readout on the Dashboard, and a "What's New" sheet. Lowers the displayed battery cutoff threshold from 10% to 5% to match a hardware-side change to the AlphaESS minimum discharge setting.

## What's New

### Solar by Block on Day Detail (T-1162)

The "Day in five blocks" panel on Day Detail now shows per-block solar generation (kWh) next to the existing load value on the morning peak, off-peak, and afternoon peak rows. Night and evening rows are unchanged.

End-to-end:

- **Backend (`derivedstats.integratePpv`)**: trapezoidal kWh + reading-sample count over a half-open window, mirroring `integratePload`'s 60s pair-gap rule, edge synthesis, and `max(ppv, 0)` clamping. `derivedstats.Blocks()` accumulates a `SolarKwh *float64` on the daylight blocks. The sample count distinguishes "no readings in window" (emits `nil`) from "samples present but integral is zero" (emits `&0.0`), so a heavy-fog day reads as zero rather than missing.
- **Persistence**: `dynamo.DailyUsageBlockAttr.SolarKwh` rides the existing atomic `UpdateDailyEnergyDerived` write path. `&0.0` round-trips as non-nil; `nil` is omitted from the stored item via `omitempty`. Post-feature sizing fixtures populate `SolarKwh` on all three daylight blocks and still serialise under the 4 KB single-RCU boundary (~2.4 KB).
- **Backfill CLI** (`cmd/backfill-solar`): walks `flux-daily-energy` rows in a configurable `--from`/`--to` Sydney-TZ date range (defaulting to the 30-day readings TTL window), recomputes `solarKwh` for daylight blocks, and patches it field-by-field onto stored blocks. `totalKwh`, `start`, `end`, `boundarySource`, `percentOfDay`, `status`, and `averageKwhPerHour` are preserved byte-for-byte (Decision 7) so partially TTL-pruned readings cannot drift historical totals. `--dry-run` logs intended writes without `UpdateItem`. Idempotent: rows whose daylight blocks all already carry `solarKwh` are skipped (Decision 4). Reversed `--from`/`--to` ranges now error with a clear message.
- **iOS Day Detail rendering**: `FluxCore.DailyUsageBlock.solarKwh: Double?` decodes from the `/day` and `/history` payloads (present, zero, null, and absent JSON forms all handled). `DayInFiveBlocksPanel` renders the per-block value in `FluxTheme.Palette.amber` next to the load figure when the API supplies one; null renders as a clean omission per AC 3.4, so days predating the feature deploy don't show false zeros. The row layout was polished to support the now-four-value daylight rows: time stacks under the block name, both values use a fixed 76 pt trailing column, and `Text` views gain `lineLimit(1)` + `minimumScaleFactor(0.85)` so they shrink rather than wrap or clip at narrower widths and larger Dynamic Type sizes.

### Dashboard "Energy left" row (T-1163)

`BatteryBlock` on the Dashboard now shows the usable kWh remaining at the current SOC:

```
(soc − cutoffPercent) / 100 × capacityKwh
```

clamped at 0. The figure reaches 0 at the same point as the existing "discharging · X · empty by HH:MM" subline. The shared math and `cutoffPercent` constant live in `FluxCore.BatteryEnergy`, also referenced by the Day Detail SOC and combined battery charts so the dashed cutoff line tracks the same value. Day Detail / History callsites omit the new input, so the row stays hidden where there is no live SOC.

### What's New sheet (T-1112)

New `WhatsNew` module in `FluxCore`:

- A typed catalogue (`WhatsNewCatalogue.releases`) of `WhatsNewRelease { version, date, highlights }` with each highlight categorised as New / Improved / Fixed.
- A `Comparable` `WhatsNewVersion` parser: `1.10 > 1.9`, `1.2 == 1.2.0`.
- A pure `WhatsNewCoordinator` mapping `(catalogue, installed, lastSeen, hasAnyFluxPref)` to one of `present | silentSet | skip`. First-launch users (no Flux preferences ever written) see nothing — only existing users get the sheet on a version bump.
- A SwiftUI `WhatsNewSheet` grouping highlights into New / Improved / Fixed.

`AppNavigationView` auto-presents the sheet once per cold launch on a version bump; `SettingsView` exposes a "What's New" row that re-opens the latest entry. `lastSeenWhatsNewVersion` and `hasAnyFluxPreferenceWritten` are stored in the App Group `UserDefaults`. Coordinator/sheet tests cover every row of the design's decision table; sheet tests smoke three fixtures via `UIHostingController` / `NSHostingController`. `specs/whats-new/implementation.md` documents the design at three levels.

## Notable Behaviour Changes

- **Battery cutoff threshold lowered from 10% to 5%**. Matches a hardware-side change to the AlphaESS minimum discharge setting. The Lambda API's `cutoffPercent` constant and `battery.cutoffPercent` response field now report 5. The dashed cutoff line on the SOC and combined battery charts in Day Detail shifts down accordingly. The "empty by HH:MM" subline and "Energy left" row both extrapolate to the new threshold. The V1 product spec is updated to match.

## Upgrade Notes

- **No infrastructure changes** required. The `solarKwh` field is additive on `flux-daily-energy`; existing rows decode unambiguously as `nil` until they're rewritten by either the hourly summarisation pass (for new days) or the backfill CLI (for past days within the readings TTL window).
- **To populate `solarKwh` on past days**, run the backfill CLI against your DynamoDB endpoint:
  ```bash
  go run ./cmd/backfill-solar --from 2026-04-09 --to 2026-05-09
  # add --dry-run first to see what it would write
  ```
  The CLI defaults to the last 30 days (matching the readings TTL). Days outside that window have no readings to integrate and will be skipped.
- **iOS / macOS**: standard App Store / TestFlight update. The What's New sheet auto-presents on first launch after upgrade for existing users.
