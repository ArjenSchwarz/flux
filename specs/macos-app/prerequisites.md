# Prerequisites for Mac App (T-1081)

These manual steps must be completed by the user in Xcode and App Store Connect before or during implementation. None can be performed by the coding agent.

## Before Starting

- [ ] **Add "My Mac" run destination on the Flux app target** — Xcode → Project → Flux target → General → Supported Destinations → click "+" → "Mac". Set `SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD = NO` so the destination is true native macOS, not "Designed for iPad".
- [ ] **Add "My Mac" run destination on the FluxWidgetsExtension target** — same flow as above. Set `SUPPORTS_MAC_DESIGNED_FOR_IPHONE_IPAD = NO`.
- [ ] **Confirm `MACOSX_DEPLOYMENT_TARGET = 26.0` (or higher)** is set on both targets — already present in the project; verify after adding the destinations.

## Before Code Task 5 (`iCloudURLMirror`)

- [ ] **Enable iCloud capability on the Flux target with "Key-value storage" sub-option ticked** — Xcode → Flux target → Signing & Capabilities → "+ Capability" → iCloud → check "Key-value storage" only (not "iCloud Documents", not "CloudKit"). This adds the `com.apple.developer.ubiquity-kvstore-identifier` entitlement to the macOS-variant entitlements file.
- [ ] **Confirm the entitlement value is `$(TeamIdentifierPrefix)$(CFBundleIdentifier)`** — Xcode generates this by default; verify in `Flux-macOS.entitlements` after the capability is added.

## Before Code Task 10 (FluxApp wiring)

- [ ] **Create `Flux/Flux/Flux-macOS.entitlements`** with the following keys (in Xcode, duplicate `Flux.entitlements` and add the macOS-specific keys, OR create via the iCloud capability flow above which generates it):
  - `com.apple.security.app-sandbox = true`
  - `com.apple.security.network.client = true`
  - `com.apple.security.application-groups = [group.me.nore.ig.flux]`
  - `keychain-access-groups = [$(AppIdentifierPrefix)group.me.nore.ig.flux]`
  - `com.apple.developer.ubiquity-kvstore-identifier = $(TeamIdentifierPrefix)$(CFBundleIdentifier)`
- [ ] **Wire per-platform entitlements** on the Flux target — Build Settings → Code Signing Entitlements → set the macOS-destination value to `Flux/Flux-macOS.entitlements` (iOS keeps `Flux/Flux.entitlements`). Use either `CODE_SIGN_ENTITLEMENTS[sdk=macosx*]` or the per-destination Build Settings override.
- [ ] **Strip `aps-environment` and `UIBackgroundModes` from the macOS Info.plist** — either by maintaining a separate `Flux-macOS.Info.plist` referenced via `INFOPLIST_FILE[sdk=macosx*]`, or by using `INFOPLIST_KEY_*` build settings to override per platform. `aps-environment` will trigger a sandbox warning on Mac if left in.

## Before Code Task 21 (Widget bundle Mac registration)

- [ ] **Add `com.apple.security.network.client` to the existing iOS widget entitlements** — required even on iOS because the widget extension fetches independently per Decision 13. Edit `Flux/FluxWidgetsExtension.entitlements` to add the key.
- [ ] **Create `Flux/FluxWidgetsExtension-macOS.entitlements`** with:
  - `com.apple.security.app-sandbox = true`
  - `com.apple.security.network.client = true`
  - `com.apple.security.application-groups = [group.me.nore.ig.flux]`
  - `keychain-access-groups = [$(AppIdentifierPrefix)group.me.nore.ig.flux]`
- [ ] **Wire per-platform entitlements** on the FluxWidgetsExtension target — same approach as the host (CODE_SIGN_ENTITLEMENTS conditioned on macosx SDK).

## Before TestFlight Mac submission

- [ ] **Add macOS as a platform on the existing Flux app record in App Store Connect** — App Store Connect → My Apps → Flux → "+" next to Platforms → Add macOS. This creates the Mac SKU under the same `me.nore.ig.Flux` bundle identifier (Decision 16).
- [ ] **Configure macOS app icon** — if no Mac-specific icon variant exists, add the appropriate icon sizes to `Assets.xcassets`.
- [ ] **Verify Provisioning Profile for the Mac variants** is generated by Xcode (automatic signing) or created manually in the developer portal.

## Notes

- Hand-editing `pbxproj` is unavoidable for the destination/entitlement/Info.plist changes above. Style guide §1 ("Don't hand-edit pbxproj") refers to source-file management; build-setting changes are made via Xcode UI and the resulting diff is reviewed.
- Prerequisites that block specific tasks reference the task number from `tasks.md`.
- App Store Connect setup can be deferred until the build is ready to submit; the code work does not depend on it.
